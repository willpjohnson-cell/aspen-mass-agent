How it works

Evidence before conclusions

A beat fetches the pages it watches one at a time and stores exactly the bytes the server sent. Nothing is cleaned or reformatted. Every row of extracted data carries the SHA-256 of the file it came from, so any claim on these pages can be checked against the bytes behind it.

Three verdicts, and no fourth

Rules are configuration, not code. Each one is evaluated against every archived page and returns compliant, not compliant, or indeterminate with a reason. A rule whose evidence is missing returns indeterminate rather than a guess, and no page is skipped. Across every beat that is currently 0 compliant, 0 not compliant, and 643 indeterminate.

Only a person promotes a finding

A not-compliant verdict becomes a finding with the status pending. It appears publicly only after someone reviews it and sets its status to confirmed in the findings file. There is no automatic promotion and no flag that creates one; exactly one line in this codebase writes a finding status, and it writes pending.

When a page was first seen, and how well that is known

Notice rules depend on knowing when something became visible, so each page carries a first-seen timestamp with a confidence. Bounded means an earlier run recorded the page as absent and a later one found it, placing its appearance inside a known window. Unbounded means the page was already there the first time anything looked; it existed at some unknown earlier time. An unbounded observation is never used to produce a notice figure, whatever the arithmetic would say.
