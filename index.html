The Monitor

A platform for building agents that watch government activity, archive it byte for byte, and detect what changed.

What it is

A beat is an agent that watches one government surface. You declare it in a YAML file: where its pages live, how politely to fetch them, which fields to read, and which rules to apply. The platform does the rest — fetching on a schedule, storing the bytes exactly as the server sent them, and comparing every page against the last time it looked.

How a beat works

Declared, not coded

A beat is a beat.yaml and a parse.py. The config carries the URL pattern, the id range, the delay between requests, the fields to extract and the rules to evaluate. The parser turns one fetched page into a flat record. Nothing else about a jurisdiction lives in the platform.

Fetches on a schedule, politely

Pages are fetched one at a time with a configured delay and no parallelism; the runner refuses to parallelise. Every request is logged with its status and timestamp, including the ones that return nothing.

Archives the bytes

Each page is stored exactly as the server sent it, and every extracted row carries the SHA-256 of the file it came from. When a page's content changes, the bytes being replaced are kept, so both versions stay in the archive and a change links to each of them.

Diffs what the page says, not what it shipped

A run compares the hash of the parsed fields rather than the hash of the raw bytes, because pages routinely carry markup that changes on every request. On the last full run that distinction separated 4 real changes from 639 pages whose bytes differed and whose content did not.

Evaluates declarative rules

Rules are configuration too. Each is evaluated against every archived page and returns compliant, not compliant, or indeterminate with a reason. There is no fourth outcome, no default and no skipped page: a rule that lacks the evidence to decide says so rather than guessing.

A person promotes a finding, never the engine

A not-compliant verdict enters a review queue as pending. It becomes public only when someone reviews it and marks it confirmed. Exactly one line in the codebase writes a finding status, and it writes pending.
