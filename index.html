The Monitor

It archives government web pages and records when they change.

What this does today

One beat is running. It archives hearing pages published by the Massachusetts General Court byte for byte, re-fetches every one of them on a schedule, and records what changed between runs. That is change detection and provenance, and it is the part of this project that works.

643 pages are archived. 4 changes have been detected and each one links to the stored bytes from before and after it. Every extracted row carries the SHA-256 of the file it came from.

What the rule layer has produced: nothing

The platform can evaluate declarative rules against archived pages and return one of three verdicts. Against the only source it currently watches, it has returned none of them.

notice-10-day on ma-hearings: no verdict on any of 643 pages, and it cannot return one against this source.

Across 643 archived pages the rule has returned 0 compliant, 0 not compliant, and 643 indeterminate.

The ten-day clock in Joint Rule 1D runs from the moment a committee notifies the Sergeant-at-Arms. The Legislature does not publish that date anywhere on malegislature.gov, so the archive does not hold it and no amount of further collection will produce it. first_seen records when this platform first saw a hearing page, which is a different event. Measuring one against the other would produce a number that looks like a notice figure and is not one. The rule is kept because the requirement is real and the gap is worth stating.

The rule, its citation, and the per-page reasons.

This is a limit of the source, not a bug in the rule engine and not something more collection will fix. It is recorded here rather than left for a reader to infer from a column of zeros.

How the archive works

The bytes are the evidence

Pages are fetched one at a time and stored exactly as the server sent them. Nothing is cleaned or reformatted. When a page's content changes, the bytes being replaced are kept, so both versions remain.

Content changes, not byte changes

This source regenerates a weather widget and a per-request form token on every response, so the raw bytes of every page differ on every fetch. A run therefore compares the hash of the parsed fields rather than the hash of the bytes. In the last full run that distinction separated 4 real changes from 639 pages that differed only in that per-request markup.

First seen, and how well that is known

Each page records when it was first observed, with a confidence. Bounded means an earlier run recorded the page as absent and a later one found it. Unbounded means it was already there the first time anything looked. All 643 pages in this archive are unbounded, because nothing looked before the first collection, and an unbounded observation is never used to produce a notice figure.
